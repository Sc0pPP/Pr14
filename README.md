# Практическая работа №14 - Приложение "Кинотеатр"

## Информация о проекте

**Группа:** 3ИСИП323  
**Разработчики:** Зевакин, Шпилько  
**Технологии:** Avalonia WPF, C#, MSTest

## Описание

Проект состоит из двух частей:

1. **WPF приложение "Кинотеатр" на Avalonia** - десктопное приложение для управления кинотеатром с системой бронирования билетов
2. **Unit тесты** - набор модульных тестов для проверки корректности работы модулей авторизации и регистрации

## Структура проекта

### Часть 1. Основное приложение (Avalonia)

#### Главная страница
- Вывод фильмов в виде сетки с информацией:
  - Обложка фильма
  - Название
  - Рейтинг
  - Дата начала показа
  - Возрастной рейтинг
- Строка поиска по фильмам
- Сортировка фильмов по критериям (Название, Рейтинг)
- Система входа и регистрации аккаунта
- Кнопка перехода на личную страницу

#### Страница выбранного фильма
- Детальная информация о фильме:
  - Картинка (постер)
  - Название
  - Краткое описание
  - Рейтинг
  - Жанры
- Список доступных сеансов с указанием:
  - Дата и время сеанса
  - Номер зала
  - Рейтинг зала

#### Страница выбранного сеанса
Доступна только авторизованным пользователям.

- Визуальная схема зала со всеми местами
- Возможность выбора свободных мест
- Отображение занятых мест (недоступны для выбора)
- Кнопка оформления билета

#### Страница оформления билета
- Информация о заказе:
  - Название фильма
  - Номер зала
  - Дата и время сеанса
  - Выбранное место
  - Цена билета
- Кнопка подтверждения покупки
- После подтверждения - возврат на главную страницу

#### Личная страница пользователя
- Информация об аккаунте пользователя
- История всех приобретенных билетов

### Часть 2. Модуль тестирования (UnitTest)

Проект содержит два основных класса тестов для проверки функционала авторизации и регистрации пользователей приложения кинотеатра.

#### AuthTests - тесты модуля авторизации

**Метод:** `Auth(login, password)`

**Возвращаемое значение:**
- `true` - успешная авторизация
- `false` - ошибка авторизации

**Тестовые пользователи:**
- admin / admin
- user1 / 1234
- petya / qwerty

**Покрытие тестами:**
- `AuthTest()` - базовый тест авторизации
- `AuthTestSuccess()` - позитивные тесты (успешный вход)
- `AuthTestFail()` - негативные тесты (отклонение входа)

**Проверяемые сценарии:**
- Успешный вход с корректными данными
- Отклонение при пустом логине
- Отклонение при пустом пароле
- Отклонение при пустых обоих полях
- Отклонение при логине/пароле из пробелов
- Отклонение при несуществующем логине
- Отклонение при неверном пароле
- Отклонение при неверном регистре пароля
- Отклонение при полностью неверных данных

#### RegistrationTests - тесты модуля регистрации

**Метод:** `Registration(login, password, confirm)`

**Возвращаемое значение:**
- `true` - успешная регистрация
- `false` - ошибка регистрации

**Существующие пользователи в базе:**
- admin / admin
- user1 / 1234

**Покрытие тестами:**
- `RegistrationTestSuccess()` - позитивные тесты (успешная регистрация)
- `RegistrationTestFail()` - негативные тесты (отклонение регистрации)

**Проверяемые сценарии:**
- Успешная регистрация с уникальным логином и совпадающими паролями
- Отклонение при пустом логине
- Отклонение при пустом пароле
- Отклонение при пустом подтверждении пароля
- Отклонение при всех пустых полях
- Отклонение при логине из пробелов
- Отклонение при занятом логине
- Отклонение при несовпадающих паролях
- Отклонение при комбинации нескольких ошибок

```bash

```

## Логика валидации

### Авторизация
1. Проверка на пустые/пробельные значения
2. Поиск пользователя по логину
3. Сверка пароля (с учётом регистра)

### Регистрация
1. Проверка на пустые/пробельные значения
2. Проверка уникальности логина
3. Проверка совпадения пароля и подтверждения

## Результаты тестирования

Все тесты проверяют граничные случаи и типичные ошибки пользователей, обеспечивая надёжность системы авторизации и регистрации.
